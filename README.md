# 私聊历史查询

把 AstrBot 只在群聊里提供的「查询群聊历史」能力，搬到**私聊**里：
模型可以按关键词、条数、起止时间，查询**当前这个用户和机器人**的私聊记录。

群聊照旧用本体自带的那套，这个插件不碰、也不会在群聊里重复挂工具。

## 为什么需要它

AstrBot 本体有两个前提：

1. 「持久化群聊消息记录」只在**群聊**里落库（`provider_ltm_settings.group_message_history_enable`）；
2. 查询工具 `get_group_message_history` 只在群聊消息的请求里挂载，并且第一句就检查
   `event.get_message_type() != MessageType.GROUP_MESSAGE`，私聊直接返回错误。

也就是说，私聊消息默认根本不会进平台消息历史表，自然也没得查。
所以这个插件做两件事：**先把私聊消息记下来，再在私聊里给模型一个查询工具**。

## 装法

1. 把压缩包 `astrbot_plugin_private_history.zip` 在 AstrBot 的插件管理里导入；
2. 确认插件已启用（默认就是启用的）；
3. 直接私聊机器人即可，不需要额外配置。

只记录**安装并启用之后**的新消息，装之前的老聊天不在库里。

## 配置项

| 配置 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| 启用私聊历史查询 | 开 | 开/关 | 关掉后既不记录，也不挂工具 |
| 默认返回条数 | 20 | 1～100 | 模型没指定条数时用这个值 |
| 单条最多多少字 | 200 | 10～2000 | 超长单条截断，末尾补省略号 |
| 一次返回的总长度上限 | 4000 | 200～20000 | 超了从最旧的开始丢，末尾注明还剩多少条 |
| 每个私聊会话保留多少条 | 1000 | 50～20000 | 超出的旧记录自动删除，避免数据库无限增长 |

## 给模型的工具

- 工具名：`get_private_chat_history`
- 只在**私聊**请求里临时挂到 `req.func_tool`，群聊请求里不存在这个工具
- 参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `keyword` | 字符串，可选 | 关键词，不区分大小写；空表示不过滤 |
| `limit` | 整数，可选 | 条数，默认 20，最大 100（超了按 100） |
| `start_time` | 字符串，可选 | 开始时间，含边界 |
| `end_time` | 字符串，可选 | 结束时间，含边界；只写日期表示包含当天整天 |

时间支持这些写法：

```
2026-11-02
2026-11-02 15:33
2026/11/02
2026年11月2日 15:33
11月2日                 （当年）
昨天 / 前天 / 大前天
今天 15:30
15:30                    （今天）
```

认不出来的时间会原样告诉模型「无法识别的时间：xxx」，不会瞎猜。

返回示例（按时间正序，一行一条）：

```
2026-11-02 15:33 用户：今天吃什么
2026-11-02 15:33 机器人：你想吃啥呀
```

查不到时只回一句：`没有找到符合条件的记录`。

## 隔离怎么保证

- 查询用的 `platform_id` 和 `user_id` **全部来自当前事件**
  （`event.get_platform_id()` + `event.unified_msg_origin`），
  工具的四个参数里没有任何一个能指定会话、用户或群；
- 数据层用本体的 `message_history_manager.get(platform_id=..., user_id=...)`，
  这两个条件同时相等才会命中，天然按「平台 + 会话」隔离；
- 工具执行时还会再检查一次消息类型，不是私聊就直接返回错误，
  所以就算被错误地挂到群聊请求上，也拿不到数据；
- 只读当前会话，不跨平台、不跨群、不跨人。

## 已知边界

- **只记文字与占位符**：图片、语音、视频、文件按 `[Image]`、`[Record]` 之类占位保存，
  和本体群聊历史的做法一致；
- **指令回复不记录**：机器人用指令直接回复（不走模型）的那条不会落库，
  因为插件只监听模型回复事件；
- **网页聊天不重复记**：网页聊天平台（webchat）自己有记录方式，本插件跳过它，
  也不在网页聊天里挂这个工具；
- **只保留最近的 N 条**：超过「每个私聊会话保留多少条」的旧记录会被自动删除；
- **时间以服务商时区显示**：数据库里存的是 UTC，插件按 AstrBot 的 `timezone`
  配置转成本地时间再给模型看；
- 删掉插件不会自动清理已经写进平台消息历史表的私聊记录；需要的话在
  AstrBot 的数据管理里按会话清理。

## 参考的本体实现

- `core/tools/message_tools.py` 里的 `GetGroupMessageHistoryTool`
  （工具名、参数、`MessageType.GROUP_MESSAGE` 判定、内容拆分、CSV 输出）；
- `core/astr_main_agent.py` 里挂载这个工具的那段

  （读写都走它，不直连数据库）。

## 关于工具名为什么不是中文

需求上想要「中文可读的名字」，但工具名会原样进服务商的函数调用协议。
DeepSeek、OpenAI 等接口要求函数名匹配 `^[a-zA-Z0-9_-]{1,64}$`，
连点号都会被拒绝（中文更不行），一旦不合法，**整次请求**都会报错，聊天直接不可用。
所以工具名用 ASCII 的 `get_private_chat_history`，中文可读性放在工具描述、
插件显示名（私聊历史查询）和帮助文案里。
